# Batch 2 Bug Classification (Issues #12964 to #11590)

## Bugs Found

- **#12964** - Possible race condition observed on FreeBSD CI — Intermittent linker failure (library not found) indicates a race condition in dune's build process
- **#12924** - `$DUNE_WORKSPACE` should be cleared in `dune pkg` sandboxes — Environment variable leaks into nested dune calls in sandboxes, causing incorrect behavior
- **#12900** - dune hangs in mdx tests waiting for _build/default/_build/.rpc/dune — Dune hangs indefinitely when background process is used in mdx tests; regression in behavior
- **#12897** - breakage with `dune format-dune-file` and `opam-dune-lint` — Breaking change requiring `(lang ...)` field breaks existing tools that relied on prior behavior
- **#12866** - Adding constraint to `ocamlformat` developer tool fails — Internal crash ("as_outside_build_dir_exn") when adding constraints to dev tool lock directories
- **#12855** - Depext not building at all (and no hint) when no `libraries` field — System dependencies silently not built and no error/hint given, leading to confusing runtime failures
- **#12854** - `--display=quiet` has no effect on `--root`-changing messages — The `--display=quiet` flag fails to suppress "Entering/Leaving directory" messages, contrary to expected behavior
- **#12818** - If dune tools install fails to install a tool it can break a user's environment — Failed tool installation (due to tar incompatibility on OpenBSD) leaves the environment in a broken state where `dune build` no longer works
- **#12752** - RPC builds don't transfer warnings to the client — Non-fatal warnings are silently swallowed; RPC client reports "Success" without showing build warnings
- **#12725** - [RPC] Eager watch mode doesn't register promotions at all — Promotions via `dune promote` are completely ignored during eager watch mode
- **#12715** - RPC system hanging non-deterministically on eager watch mode — Server stops answering requests and clients hang forever in eager watch mode
- **#12700** - under-specified dependencies for build env — Package build rules don't account for environment changes, causing incorrect builds
- **#12660** - dune forwarding rpc occasionally gets EINVAL backtrace — Uncaught exception (Unix.EINVAL from setsockopt) during RPC forwarding causes crash
- **#12609** - dune build hangs if curl not installed — Build hangs indefinitely after reporting curl is missing instead of exiting with an error
- **#12611** - [Merlin] Curious Unbound module issue — Merlin/LSP reports false "Unbound module" errors depending on alphabetical ordering of executables in a dune file
- **#12544** - The error message "optional with unavailable dependencies" is hard to digest — Error message is misleading and does not point to the actual missing transitive dependency
- **#12535** - Crash when compiling diffast-cli.0.3.5.1 on Windows — Dune crashes with internal error on Windows (MinGW/Cygwin) during compilation
- **#12475** - [pkg] build a simple unikernel — Dune pkg fails to build packages due to incorrect handling of directory targets in fetched archives
- **#12439** - Confusing message with erroneous rules — Error message "You cannot use %{target} with inferred rules" is confusing when the actual issue is a missing `(target ...)` field
- **#12431** - Can't build ocamlbuild on Windows: `Error: opendir(): No such file or directory` — Build failure on Windows due to symlinks in ocamlbuild source; also `dune clean` fails afterwards
- **#12429** - Error fetching compiler package on Windows relating to directory targets — Dune fails to recognize directory targets it created on Windows, claiming the action didn't produce them
- **#12390** - `dune pkg` no longer picks up the compiler from its cache — Regression in 3.20: compiler is rebuilt from scratch every time instead of being picked up from cache
- **#12322** - Don't include .output files with "default" targets — `dune build` unnecessarily executes test binaries (building `.output` files) causing confusing error reports for failing tests
- **#12317** - User-defined rules cannot be added to the 'empty' alias — Upgrading lang dune to 3.20 triggers an error with no location information, making it impossible to diagnose
- **#12309** - `--cache=disabled` is triggering some re-compilation — Building with `--cache=disabled` incorrectly triggers recompilation of already-built artifacts
- **#12143** - `dune utop` in a `dune pkg` managed workspace can fail with unmet library dependencies — `dune utop` fails because test-only dependencies (via `:with-test`) are picked up by utop but not actually installed
- **#12122** - Hardlinks on Haiku not allowed — Package management fails on Haiku because hardlinks for cookies fail and there is no way to change sandbox mode
- **#12109** - Empty Coq/Rocq theory leads to package error — `dune build` incorrectly claims a package has no stanzas when it has a `coq.theory` stanza
- **#12108** - Poor error reporting in cram tests, take 2 — `set -o pipefail` causes `***** UNREACHABLE *****` output instead of a meaningful error; stderr from shell is not reported
- **#12104** - Cram tests don't pick up env variables — Inline environment variable assignments (e.g., `VAR=val command`) are not picked up by commands in cram tests
- **#12103** - [pkg] Passing `-j` to `dune build` causes the compiler package to be rebuilt — Changing the `-j` parallelism flag causes all dependencies including the compiler to be unnecessarily rebuilt
- **#12075** - Building dune crashes with Unexpected_find_result for pp library — `make release` crashes with internal error "Unexpected find result" for the `pp` library
- **#12063** - Dune segfaults during bootstrap on ppc64 — Generated dune.exe is corrupt and segfaults on ppc64 Darwin during bootstrap
- **#12018** - crash when using ctypes stanza — Internal error "link_many: unable to find module" crash when using ctypes stanza with `--profile release`
- **#12007** - dune build @ocaml-index builds too many files — The `@ocaml-index` alias incorrectly builds cross-compilation targets and unreferenced files
- **#11999** - Dune pkg don't find dune-site plugins for dependencies — Executables using dune-site plugins cannot find plugins from package-managed dependencies
- **#11941** - Dune overwrites the user provided debug flag in foreign stubs — Dune appends `-g` after user-specified C flags, making it impossible to disable debug info with `-g0`
- **#11932** - baffling error message when a "dune lang" version is too new — Error message when `(lang dune X)` version is unsupported is confusing and misleading
- **#11923** - Dune builds C stubs with `bytecode_cflags` and never `native_cflags` — Wrong compiler flags used for native C stubs; can cause crashes with ThreadSanitizer
- **#11848** - Test stanza allows expectation files to be generated — This breaks promotion in the test stanza
- **#11836** - Dune cannot build empty `coq.theory` — Fatal exception when building a coq.theory with `(modules )` that excludes all Coq files
- **#11774** - `dune install` with an out-of-workspace build directory produces absolute paths in dune-package files — Absolute build paths leak into installed dune-package files, making distributed packages unusable
- **#11633** - odoc required by cram depending on objs/byte — Cram tests with `(deps (glob_files .foo.objs/byte/*))` incorrectly require odoc to be installed
- **#11631** - dune watch rpc is sending off by minus one lines inconsistently — Diagnostic line numbers are off by one compared to compiler output, and the offset is inconsistent
- **#11618** - Internal error: [as_in_build_dir_exn] called on something not in build dir — Internal crash when building Rocq/Coq projects with opam-installed plugins; should be a user-facing error
- **#11615** - Dune can only understand opam repos matching the layout of opam-repository — Dune fails to find packages in opam repos that use a different (but valid) directory layout
- **#11593** - dune takes >2GB of RAM building some targets of frama-c.30.0 — Excessive memory usage (>2GB) when building certain targets, suggesting a resource leak or inefficiency
- **#11590** - Support MSVC command-line flags syntax with pkg-config in dune-configurator — pkg-config returns Unix-style flags to MSVC compiler, causing build failures on Windows
- **#12551** - pkg: `dune utop src/...` fails because of duplicate .cmas: tools and pkgs — `dune utop` crashes with "Duplicated implementations" errors due to conflicting .cma files between dev tools and packages
