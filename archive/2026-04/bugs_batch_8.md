# Batch 8 Bug Classification (Issues #4962 to #3876)

## Bugs Found

- **#4962** - Vendored dependencies interacting poorly with esy and opam — Vendored deps cause incorrect behavior with esy/opam package managers
- **#4957** - Using `findlib.dynload` shouldn't imply `-linkall` for executables — Adding findlib.dynload incorrectly forces -linkall, creating excessively large executables
- **#4949** - Remove runtime dependency on OCaml when building a pure Coq project — Dune incorrectly requires ocamlc even when building a project that needs no OCaml, producing a misleading error
- **#4895** - The documentation/value of %{system} is not consistent — The %{system} variable value does not match what the documentation claims it should be
- **#4892** - Private modules cause missing build path (in the ocaml-merlin dump) — Merlin config is missing the byte directory for libraries with private modules, causing locate failures
- **#4866** - dune doesn't cleanup all .merlin files and doesn't inform user of using them — Dune leaves behind stale generated .merlin files and doesn't inform users about the transition
- **#4816** - Optional argument for --promote-install-files breaks CLI compatibility — Dune 2.9.0 breaks backward compatibility of the --promote-install-files CLI flag
- **#4547** - Too much string escaping in overlapped dependencies error path on Windows — Error messages on Windows show excessively escaped backslashes, making paths unreadable
- **#4531** - Issues with --action-stdxxx-on-success — The option operates at the wrong level (single run vs whole action), producing unintuitive behavior
- **#4525** - Making (setenv) easy to test — When an action with setenv fails, the reproduced command omits environment variables, making it impossible to reproduce
- **#4482** - Random "Permission denied" errors on macOS ARM64 — Random compilation failures specific to macOS ARM64, working fine on other platforms
- **#4479** - interop between dune and merlin since 2.8 does not work with ppx_expect — Regression: merlin queries fail with ppx_expect after upgrading from dune 2.7.1 to later versions
- **#4468** - Error: Invalid dune file on Unicode in dune file — Dune incorrectly rejects Unicode characters in paths within dune files
- **#4457** - Documentation for determining package version is incorrect — Actual behavior of package version detection does not match what the documentation states
- **#4445** - action plugin: trying to read empty / non-existing directory raises — read_directory_with_glob raises an unhelpful error on empty or non-existing directories instead of returning empty
- **#4156** - ppxs are built in the target context in cross-compilation settings — PPX libraries are incorrectly built in the target context instead of the host context during cross-compilation, causing build failures
- **#4130** - pkg-config not resolved on windows with dune configurator — C.Pkg_config.get always returns None on Windows even when pkg-config works correctly
- **#4123** - -opaque option breaks equivalence between release and dev compilation in presence of [@inline always] — dune build fails while dune build --release succeeds due to -opaque flag interaction with @inlined always
- **#4111** - Dune doesn't generate correct .merlin file when directory path contains space — Generated .merlin file has incorrect path escaping when project path contains spaces
- **#4070** - Undesired conflict between vendored library and public library by the same name — Dune incorrectly reports a conflict when a vendored library has the same name as an external one used by a different dependency
- **#4068** - Allow to create sublibraries named "opam" — Creating a sublibrary named "opam" causes symlink errors during build
- **#4051** - opam file generation: dune bound only considers toplevel project — Generated opam files have incorrect dune version bounds when nested projects use a higher dune language version
- **#4039** - flambda with -nostdlib and transitive stdlib not finding cmx — Dune fails to add stdlib during linking when it is a transitive dependency with -nostdlib, causing flambda optimization failures
- **#4021** - auto-formatting of dune files does not preserve end-of-line strings — Auto-formatter incorrectly converts end-of-line strings to regular escaped strings
- **#4018** - Cannot add absolute paths to CRAM sanitizer on Windows — Path sanitization is broken on Windows because colons in absolute paths conflict with the separator format
- **#4017** - Sanitized paths for CRAM tests in Windows mix `/` and `\` — Path sanitization fails on Windows due to inconsistent forward/back slash mixing
- **#3916** - Duplicate bounds on autogenerated opam files — Generated opam files contain duplicate dune version bounds (e.g. `{>= "2.7" & >= "2.7"}`)
- **#3913** - Dune finds non existing library conflict without (implicit_transitive_deps false) — Dune incorrectly detects a library conflict that doesn't actually exist in certain vendoring scenarios
- **#3910** - Mode `(byte shared_object)` cannot find stubs in Dune >= 2.1 — Regression from dune 2.0: byte shared object mode fails to find stubs that were found before
- **#3908** - does dune enforce complete cmxs files? — Generated .cmxs files may be missing necessary C stubs, causing dynamic linking failures
- **#3917** - Explicit executable dependencies and cross-compilation — Explicit .exe dependencies in rules resolve to cross-compiled workspace instead of host context, breaking cross-compilation
- **#4194** - Crash in Stdune__io.Make.eagerly_input_string — Dune crashes with Invalid_argument("Bytes.create") exception on arm32 when running tests
- **#4347** - Byte target can't be debugged with ocamldebug — Dune-built .bc files are missing debug symbols that ocamlc -g produces correctly
