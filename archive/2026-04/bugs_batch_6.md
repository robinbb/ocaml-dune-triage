# Batch 6 Bug Classification (Issues #7624 to #6149)

## Bugs Found

- **#7624** - In `dune_rpc_lwt` closing the output channel should also close the input channel — Closing the output channel raises `Unix.Unix_error(Unix.EBADF)` instead of returning `None` on the input channel
- **#7586** - "dune top -p <pkg>" tries to pull the dependencies of unrelated vendored executables — `dune top -p` incorrectly pulls dependencies from unrelated vendored executables
- **#7583** - What should happen when exposing code from a private package? — Compilation fails with missing `.cmi` files when re-exposing private package code through a public module, with no warning at library compile time
- **#7573** - Build failing due to existence of broken symbolic link (unused in build) — Dune fails the build when a broken symlink exists in vendored sources even though it is not used by the build
- **#7571** - env not supported in enabled_if Boolean language in library stanza — `%{env:...}` variable not allowed in `enabled_if` despite documentation saying it should be supported; documentation and behavior mismatch
- **#7568** - Dune doesn't respond to RPC methods when run in watch mode in the dune repository — RPC ping command hangs forever when dune is running in watch mode within its own repository
- **#7534** - `-p` does not detect packages in `opam/` subfolder even when `(opam_file_location inside_opam_directory)` — `-p` flag fails to find packages located in the `opam/` directory
- **#7470** - `dune-site` cannot be used in top-level REPL — Loading `dune-site` in OCaml toplevel raises `Error: Reference to undefined global 'Dune_site__Dune_site_data'`
- **#7464** - `preprocess` `per_module` dependencies are not relative — Preprocessing with action `run` in `preprocess` stanza resolves paths relative to workspace root instead of the dune file directory
- **#7460** - Cache hits "hide" warnings — When dune cache is enabled, cache hits suppress compiler warnings that should still be displayed
- **#7454** - `dune fmt` unexpectedly triggers menhir rules — `dune fmt` / `dune build @fmt` builds menhir parsers when it should not build anything
- **#7448** - Potential bug: dune commands no longer work after updating macOS to Ventura — `dune build` produces `Error: write(): Operation timed out` after macOS Ventura update
- **#7413** - Debug mapping is sometimes inconsistent with installed locations — `BUILD_PATH_PREFIX_MAP` in compiled libraries is missing package name information, causing incorrect debug source mappings after installation
- **#7223** - "I/O error" with `.pp.ml` file when running `dune build . -w` — Watch mode intermittently fails with I/O error on `.pp.ml` files that resolves on restart
- **#7222** - compiler errors have wrong relative path — Compiler errors show paths relative to the parent project root instead of the current project when building from a submodule
- **#7170** - Folders excluded from `dirs` are visited when calling `dune build @my_alias` — Directories excluded via `dirs` stanza are still visited (stat'd) during alias builds
- **#7155** - Spurious warning when a private library is in the deps of a Coq plugin — False warning triggered when a Coq plugin has a private library in its transitive dependencies
- **#7146** - Linker is invoked from unexpected directory — Linker cannot find libraries referenced with relative paths in `c_library_flags` because the linker runs from an unexpected directory
- **#7135** - Hidden folders are ignored in source_tree dep — Files in hidden directories (e.g. `.cargo/`) are silently excluded from `source_tree` dependencies with no way to include them
- **#7091** - Dune cannot handle `From ... Extra Dependency` — Dune fails to build Coq files using `From ... Extra Dependency` because non-`.v` files are not copied to the target directory
- **#7073** - ld: Error: unable to disambiguate: -shared-libgcc — Linker error when building with `(modes object)` due to conflicting `-shared-libgcc` flags
- **#7053** - Dune does not validate non-existent Coq modules being excluded — Excluding non-existent Coq modules silently accepted, and using `(modules \ I.dont.exist)` causes a `List.hd` exception
- **#7043** - Dune tests are being executed in unexpected dir while vendoring — Tests in vendored projects execute from `%{workspace_root}` instead of the vendored `%{project_root}`
- **#7034** - Dune treats warnings as errors according to the workspace `lang dune` version when building vendored packages with a more permissive `lang dune` version — Warning-as-error settings from top-level `dune-project` version are applied to vendored packages instead of respecting their own `lang dune` version
- **#6844** - Bug when linking ocaml with a dune package including a static library — Dynlink error when linking a Coq plugin that includes a Rust-built static library via foreign_archives
- **#6830** - Rule collision when multiple vendored projects contain executables with matching names — Dune errors with "Multiple rules generated" when two vendored packages both contain executables with the same public name
- **#6817** - `dune utop --watch` Appears to be broken — `dune utop --watch` does not rebuild/reload when source files change
- **#6730** - Terminal UI is broken on Windows — `--display tui` mode is completely broken on Windows
- **#6680** - OCaml toplevel sometimes fails to load default implementation for a virtual library — `#require` in toplevel fails to load default implementation for virtual libraries, causing undefined global errors
- **#6615** - `coq.theory` stanza should work on the transitive closure of the `plugins` field — Coq plugin dependencies are not transitively resolved, causing Coq to fail to find required libraries
- **#6607** - Test suite is broken when CLICOLOR_FORCE=1 — Dune's own test suite fails when `CLICOLOR_FORCE=1` is set because expect tests include color codes
- **#6598** - Confusing 'Module ... is used in several stanzas' error — Error message mentions a module name that is not in the listed stanza, making the error confusing and misleading
- **#6568** - Preprocessing with actions and future syntax cannot be used in conjunction with (instrumentation ...) — Cannot combine `preprocess` action with `instrumentation` stanza despite no inherent conflict
- **#6481** - ctypes: flags are added twice — ctypes build adds flags twice, causing linker errors (regression from dune 3.5.0 to 3.6.0)
- **#6393** - coq: native compilation failing on macos — Coq native compilation fails on macOS with linker warning about missing directory
- **#6263** - C archive for byte target not built to include dynamic dependencies — Bytecode library C stubs do not include dynamic dependencies, so `ldd` on the resulting `.so` does not show them
- **#6162** - Cache doesn't work on `opam install` — Dune cache files cannot be hardlinked inside OPAM sandbox, silently failing to populate the cache
- **#6149** - Dune does not rerun coqdep if filesystem layout changes — Dune does not reinvoke `coqdep` when files are added/removed, causing stale dependency information
